**user**: 我怎么使用speckit开发一个大数据应用开发平台？
[Timestamp: 2026/02/08 10:11:58]

**ai**: 要使用 Speckit 开发一个**大数据应用开发平台**，你可以遵循其结构化、可追溯的全流程方法论。虽然提供的上下文以“人才信息管理系统”为例，但其流程完全适用于大数据平台开发。以下是基于 Speckit 范式的具体步骤：

---

### 1. **定义项目宪章（Constitution）**
使用 `/speckit.constitution` 命令，明确大数据平台的核心约束与准则：
- **技术栈**：如 Spark/Flink + Hadoop/HDFS + Kafka + 达梦/ClickHouse
- **代码质量**：单元测试覆盖率 ≥80%，CI/CD 集成
- **数据规范**：支持结构化/非结构化数据，符合 GDPR/等保要求
- **性能指标**：TB 级数据处理延迟 <5s，支持横向扩展

输出：`@specs/constitution.md`

---

### 2. **编写详细需求规格（Specify）**
使用 `/speckit.specify`，描述平台功能：
- 用户角色：数据工程师、分析师、运维人员
- 核心功能：
  - 可视化 DAG 任务编排
  - 实时/离线数据管道构建
  - 元数据管理与血缘追踪
  - 资源监控与告警
- 交互需求：拖拽式 UI、SQL 编辑器、日志实时查看

输出：`@specs/001-bigdata-platform/spec.md`

---

### 3. **需求澄清与边界确认（Clarify）**
使用 `/speckit.clarify`，解决模糊点：
- “实时处理”指端到端延迟 ≤1 秒？
- 是否支持多租户资源隔离？
- 数据脱敏规则如何配置？

输出：`@specs/001-bigdata-platform/clarifications.md`

---

### 4. **生成 ASCII 界面原型（ASCII Design）**
使用 `/ascii-design`，基于需求自动生成文本化 UI 草图：
- 任务流编排界面
- 集群监控仪表盘
- 数据表预览面板

输出示例：
- `@ascii-ui-design/bigdata-dag-editor.txt`
- `@ascii-ui-design/cluster-monitor.txt`

---

### 5. **制定技术设计方案（Plan）**
使用 `/speckit.plan`，产出架构文档：
- **后端**：Spring Boot + JDK 17 + Flink REST API 封装
- **前端**：Vue 3 + D3.js 可视化
- **数据库**：达梦（元数据）+ HBase（原始数据）
- **接口清单**：`/api/v1/pipeline/run`, `/api/v1/metadata/lineage`
- **安全设计**：RBAC 权限模型，OAuth2.0 集成

输出：`@design/001-bigdata-platform/plan.md`

---

### 6. **拆解开发任务（Tasks）**
使用 `/speckit.tasks`，将设计分解为可执行任务：
- 后端：实现 Flink 作业提交接口（优先级 P0）
- 前端：开发 DAG 节点拖拽组件（依赖：D3.js 熟悉）
- 测试：验证 10TB 数据导入性能（需专用测试集群）

输出：`@tasks/001-bigdata-platform/tasks.md`

---

### 7. **风险分析与测试用例**
- **风险分析**（`/speckit.analyze`）：识别如“Kafka 积压导致 OOM”、“HDFS 小文件问题”等风险，输出缓解方案。
- **测试清单**（`/speckit.checklist`）：覆盖高并发提交、断电恢复、跨版本兼容性等场景。

---

### 8. **本地启动与验证**
参考现有命令调整环境：
```bash
# 前端（大数据平台 UI）
cd odin-web-ui-plus
npm install
npm run dev

# 后端（需适配大数据组件）
cd odin-web
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17.0.18"
mvn spring-boot:run  # 确保连接 Flink/Kafka 配置正确
```

> 💡 **关键提示**：Speckit 的核心价值在于**强制结构化输出**，确保从需求到代码的每一步都可审计、可回溯，特别适合复杂的大数据系统开发。
